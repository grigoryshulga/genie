# Готовые варианты vs собственная реализация

Исследование проведено 2026-09-27 по npm-реестру и исходникам пакетов (скачаны и прочитаны README и код). Все пакеты — MIT/Apache-2.0, совместимы с pi 0.87.

## Матрица требований

| # | Требование | Лучшие готовые варианты | Чего не хватает у готовых | Что сделано в genie |
|---|---|---|---|---|
| 1 | Оркестратор + фокус-группы (аналитик / исполнитель / ревьюер) | `@giladbarnea/pi-simple-team`, `@tintinweb/pi-subagents`, `pi-herdr-agents`, `pi-herdsman`, `@henryqw/pi-subagent` | Роли импровизируются моделью либо это «родитель → ребёнок» делегирование; нет жизненного цикла задачи | Фиксированные роли (`agents/*.md`), шаблоны команд (`config/default.json`), промпты ролей с обязанностями |
| 2 | Задачи локально, отдельный CLI | `beads` (`bd`, @beads/bd 1.3), `Backlog.md` (1.53), `@tintinweb/pi-tasks` (только внутри pi) | Нет ролевых прав на переходы, нет связи с командами/worktree, нет DoR/DoD | CLI `genie` + общий трекер `.genie/` (JSON на задачу), ролевые переходы, DoR/DoD, комментарии, артефакты, история |
| 3 | Прямое общение агентов без оркестратора | `pi-simple-team` (push-сообщения между всеми), `pi-herdsman` (только между лидами), `doompi-team` intercom (alpha) | У subagent-пакетов связь только через родителя | Файловые почтовые ящики: любой участник пишет любому; доставка push’ем (будит получателя), LLM оркестратора не участвует |
| 4 | Оркестратор — точка входа, доводит до готовности | — (нет пакетов с этим контрактом) | — | Статус `ready` может выставить только оркестратор; Definition of Ready проверяется кодом |
| 5 | Оркестратор — точка приёмки | — | — | Статус `done` — только оркестратор; Definition of Done: все критерии отмечены + статус `approved` от ревьюера |
| 6 | Нарезка на атомарные задачи, worktree на команду | Worktree: `pi-herdr-agents`, `@tintinweb/pi-subagents`, `@henryqw/pi-subagent`, `pi-worktree-extension`; нарезка — нигде | Worktree привязан к субагенту, а не к задаче/команде | `split` + `deps` + ready-очередь; `team_spawn` создаёт worktree `genie/<team>` на команду |
| 7 | Команда из разных моделей и провайдеров | Все основные пакеты поддерживают модель на агента | — | Модель/thinking на участника (шаблон → `roleModels` → явное указание), проверка по реестру моделей pi |
| 8 | Участники обновляют задачу, документируют, артефакты, комментарии | `Backlog.md` (implementation notes/plan) | Нет принуждения на уровне агентов | Инструмент `genie_task` для участников (comment / artifact / appendNotes / check / status), промпты ролей требуют это |
| — | ABAP | `@patimweb/pi-abap-fs` (ADT: чтение/поиск/запись/активация), `@abaplint/cli` (линтер), `@mcp-abap-adt/core` (MCP-сервер ADT) | вне скоупа | шаблон команды `abap` без git worktree, с правилами про объекты и транспорт |
| — | MCP из opencode | встроенный MCP pi (раньше `pi-mcp-adapter`) | — | Скрипт миграции: `~/.config/mcp/mcp.json` с `${VAR}` вместо секретов |
| — | LiteLLM | `pi-provider-litellm` (уже стоит) | — | Миграция: `baseUrl` + `$LITELLM_API_KEY`, метаданные моделей в `models.json` |

## Кандидаты подробнее

### Команды и общение

- **`@giladbarnea/pi-simple-team` 2.0.0** — «комната» из pi-агентов: `team_spawn`, `team_send_message`, статусы, `team_log`, долговечные сессии (переживают перезапуск), панели herdr, модель на каждого участника, вложенные команды. **Ближе всех к требованиям 3 и 7.** Минусы: команда работает в cwd главной сессии (нет worktree на команду), роли и процесс задаются моделью «на лету», нет трекера и приёмки.
- **`@tintinweb/pi-subagents` 0.19 + `@tintinweb/pi-tasks` 0.9** — клон Claude Code: `Agent`, фоновые агенты, worktree-изоляция, кастомные типы агентов (md), steering, детерминированные `SubagentWorkflow`-скрипты, общий файловый список задач с блокировками. Минус: связь только родитель ↔ ребёнок (требование 3 не выполняется), задачи — в стиле TodoWrite, без ролей/ревью.
- **`pi-herdr-agents` 2.0.4** — асинхронные субагенты в панелях herdr, управляемые worktree, persistent-специалисты. Минус: только родитель ↔ ребёнок.
- **`pi-herdsman` 0.16** — флот агентов в herdr, вложенное делегирование, `peer` между лидами, режим `/chief`. Минус: peer-сообщения только между лидами, не внутри команды.
- **`@henryqw/pi-subagent` 22.x** — строгий конвейер изолированных worktree со стадиями stage/integrate/promote. Мощно, но очень opinionated и тяжело; родитель-центрично.
- **`@groeponline/pi-agent-orchestrator` 0.19** — crews/swarms/handoffs, worktree, дашборд `/agents`, расписания. Родитель-центрично.
- **`@agimon-ai/doompi-team`** — intercom + модельная политика + граф задач; alpha, завязан на дистрибутив DoomPi.
- **`pi-subagents` (nicobailon) 0.72** — зрелое делегирование с готовыми scout/worker/reviewer/oracle, цепочки, фон. Родитель-центрично.

### Трекер задач (отдельный CLI)

- **beads (`bd`)** — граф зависимостей, ready-очередь, JSON-вывод, заточен под агентов; есть pi-интеграции (`pi-beads`, `@abix5/pi-beads`). Минусы: универсальные статусы (open/in_progress/blocked/closed) — ревью/приёмка только через соглашения и лейблы, нет прав ролей.
- **Backlog.md** — задачи как markdown-файлы в репо, CLI + MCP + веб-канбан, acceptance criteria, план и implementation notes, настраиваемые статусы. Отлично читается человеком. Минусы: нет прав ролей и связи с командами/worktree.
- **genie (свой)** — то, что реализовано здесь: жизненный цикл под ваш процесс с правами ролей и гейтами DoR/DoD.

## Варианты сборки

| Вариант | Состав | Плюсы | Минусы |
|---|---|---|---|
| **A. genie (реализован)** | `genie` + встроенный MCP pi (раньше `pi-mcp-adapter`) + `pi-provider-litellm` + herdr | Закрывает требования 1–8 целиком; процесс зашит в код (права, гейты); один трекер на все worktree | Свой код на поддержке; MVP-зрелость |
| **B. Сборка из готового** | `pi-simple-team` + `Backlog.md` или `beads` + skill с описанием процесса | Меньше своего кода; зрелое peer-общение | Процесс держится только на промптах; worktree на команду вручную; приёмка не принуждается |
| **C. Субагентный** | `@tintinweb/pi-subagents` + `@tintinweb/pi-tasks` (или `pi-herdr-agents`) | Самые отточенные UX и worktree-изоляция | Нет прямого общения агентов (требование 3) |
| **A+** | genie + трекер-бэкенд Backlog.md/beads вместо JSON | Человекочитаемые задачи в git | Нужен адаптер (решение — после интервью) |

**Рекомендация:** A (уже работает, проверено сквозным прогоном), с возможностью позже заменить хранилище трекера на Backlog.md, если важно хранить задачи в git в виде markdown. `pi-simple-team` имеет смысл только для «свободных» команд без процесса, и включать его одновременно с genie нельзя: оба регистрируют инструмент `team_spawn`.

Для ABAP (когда дойдём до линтера): `@abaplint/cli` как проверка в шаге executor/reviewer, `@patimweb/pi-abap-fs` — если понадобится работать с объектами как с файлами напрямую через ADT, без MCP.
