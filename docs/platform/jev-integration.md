# Решения с Jev

Genie использует один сервис Jev для двух задач: дополнительная оценка по запросу агента и участие в подборе новой delivery-команды. По умолчанию внешние вызовы, инструмент и все режимы влияния отключены. Работающая команда не меняет модель на каждом ходе.

## Включение

1. Укажите ключ **TypeSafe** в личных ключах (`/settings/me/keys`) или в общих ключах провайдеров сервера. Используется ключ инициатора, затем общий ключ. `TYPESAFE_API_KEY` сервера используется только в локальном режиме без учётных записей. Агенту не нужно получать ключ Jev для работы с инструментом.
2. Откройте **Настройки → Проект → Решения с Jev**. Администратор проекта разрешает передачу контекста во внешний TypeSafe API.
3. Независимо выберите режимы для состава команды, модели и усилий. Добавьте доступные альтернативные шаблоны и проверенные профили `(model, thinking)` с описаниями применимости и разрешёнными ролями.
4. При необходимости включите инструмент и отметьте роли, которые вправе обращаться к нему. Его можно включить при выключенном автоматическом подборе.
5. Сначала используйте наблюдение или совет. Проверяйте качество выбора на задачах проекта перед автоматическим применением.

Профиль — разрешение администратора использовать конкретную пару для конкретных ролей. Проверьте её доступность для инициаторов, работу инструментов и поддержку уровня усилий. Jev получает описание профиля; он не обнаруживает возможности новых моделей по их названиям. Отсутствие альтернатив оставляет соответствующую часть предложения без изменений.

Режимы:

- **Выключено (`off`)** — Jev не оценивает этот выбор.
- **Наблюдение (`observe`)** — оценка сохраняется в журнале, но не подаётся менеджеру при запуске и не меняет предложение.
- **Совет (`advise`)** — рекомендацию можно посмотреть до запуска; оценка при запуске также приходит оркестратору отдельным сообщением. Предложение автоматически не меняется.
- **Совместное решение (`joint`)** — уверенное расхождение останавливает запуск до пересмотра или обоснованного отклонения.
- **Автоматический выбор (`select`)** — уверенный выбор применяется в пределах настроенных альтернатив.

Модель и усилия выбираются совместимой парой. Автоматически изменяется только пара, где каждый изменяемый компонент имеет нужное полномочие. Если модель закреплена режимом, выбираются только профили этой модели; нельзя перенести усилия из профиля другой модели. Явный запуск человеком сохраняет его состав, модели и усилия. Получить предварительную рекомендацию человек может отдельно.

Состав сравнивается только между delivery-шаблонами с тем же рабочим местом. Если исходная команда содержит исполнителя или независимого ревьюера, альтернативы сохраняют эти классы. Доступ к ролям, стадии, число участников, активная команда и бюджет повторно проверяются обычным рантаймом. Разбор идеи и refinement-команды не проходят автоматический подбор.

## Инструмент агента

CLI и MCP используют одну операцию. Пример CLI (задача должна существовать):

```sh
genie decision evaluate --request '{
  "task": "G-123",
  "purpose": "next-diagnostic-step",
  "state": {
    "goal": "Найти источник задержки экспорта",
    "facts": ["Большая часть времени приходится на чтение из базы"],
    "constraints": ["Не менять публичный API"]
  },
  "questions": {
    "next": {
      "type": "choice",
      "instructions": "Какую проверку первой выполнить для этой задачи?",
      "criteria": {
        "query_plan": "Посмотреть план запроса и использование индексов",
        "repeated_reads": "Измерить число повторяющихся чтений",
        "need_evidence": "Сначала нужен более точный профиль задержки"
      }
    }
  }
}'
```

MCP: инструмент `genie_decision`, аргументы `{"action":"evaluate","request":{...}}`, где `request` — объект из примера. Для агента поле `task` может браться из его назначения; контекст и факты он передаёт явно. Данные чужой задачи автоматически не подставляются. Разрешение роли и область назначения проверяются HTTP API независимо от способа вызова.

Поддерживаются `choice` (2–255 именованных вариантов), `score` (2–10 упорядоченных описаний) и `bool` (описания `true` и `false`). Публичный `bool` преобразуется в TypeSafe `noul`. До 32 вопросов в одном вызове; все они независимы и оцениваются над общим state. Зависимое решение требует следующего вызова.

Ответ включает идентификатор записи, состояние `ok`, `uncertain` или `unavailable`, фактическую модель Jev, типизированные ответы, вероятности, уверенность, usage, стоимость и задержку. У Choice поле `qualified` показывает прохождение порогов. Неопределённый ответ сохраняется, но не даёт права на автоматическое изменение. Неверный запрос или запрещённый доступ возвращают ошибку API, а не выдуманное решение.

Инструмент не исполняет выбранное действие и не генерирует объяснение свободным текстом. При необходимости агент формулирует своё объяснение отдельно и проверяет гипотезу. `confidence` характеризует определённость выбора, а не вероятность успешной реализации.

## Предварительный выбор команды

```sh
genie team recommend G-123 --template standard
genie team recommend G-123 --member executor --member reviewer
genie team spawn G-123 --member executor:provider/model:high --member reviewer
genie decision list --task G-123
genie decision show 42
genie decision policy
```

`recommend` возвращает рекомендуемый план, оценки и сообщения. Он не создаёт workspace, команду или агентские сессии; это оплачиваемая оценка, учитываемая в лимитах задачи. В режиме наблюдения исходный план сохраняется. В советующем режиме менеджер сравнивает рекомендацию с требованиями до `spawn` и выбирает шаблон или участников самостоятельно.

В `joint` менеджер читает расхождение и либо меняет предложение, либо обосновывает сохранение исходного:

```sh
genie team spawn G-123 --template standard \
  --decision-override 'Критерий требует отдельного аналитика для проверки формата исходных данных.'
```

Причина должна содержать 12–2000 знаков и остаётся в журнале. Override сохраняет целиком исходный план, чтобы не смешивать несовместимые части профилей. Повтор идентичной успешной или неопределённой автоматической оценки использует уже записанное свидетельство. Ошибку можно повторно оценить после исправления подключения; старый вызов остаётся в истории и лимитах. Зависшая после прерывания запись допускает новый вызов по истечении двойного таймаута плюс секунды. Изменение постановки, альтернатив, настроек или модели Jev делает ключ оценки другим. Повторный запуск уже занятой задачи не создаёт вторую команду.

Override доступен агенту только при расхождении в режиме `joint`; обойти чистый `select` этим флагом нельзя.

Совет/наблюдение в автоматизациях используют тот же сервис, что CLI и MCP: все пути начального запуска сходятся в `spawn_team`. Режим `joint` может отказать шагу автоматизации; если ей нельзя останавливаться для пересмотра, выберите `advise` или `select`. Изменение режима Jev не меняет автономность проекта, приёмку и право на merge.

## Настройка сервера и хранение

Проектные настройки и последние оценки доступны в вебе. API:

- `GET/PUT /api/decisions/policy` — текущая политика проекта; запись только людям с правами администратора проекта.
- `POST /api/decisions/evaluate` — явный запрос; требуется включённый инструмент, разрешённая роль, задача в области назначения и право записи.
- `GET /api/decisions?task=G-123`, `GET /api/decisions/42` — история; агент обязан указать свою задачу, область проверяется также при чтении отдельной записи.
- `POST /api/teams/recommend` — предварительный план с теми же полями, что у запуска команды; только оркестратор или человек.

Как и остальные API, запросы ограничены выбранным проектом и обычной авторизацией Genie. Веб показывает последние 100 записей проекта. Записи остаются после остановки команды и доступны для разбора результата.

В `<data>/config.json` необязательный раздел `decisions` задаёт серверные параметры:

```json
{
  "decisions": {
    "enabled": true,
    "baseUrl": "https://api.typesafe.ai/v1/",
    "model": "jev-1.13.0",
    "timeoutMs": 5000,
    "maxRequestBytes": 32000,
    "inputPrice": 0.042,
    "defaults": {
      "allowExternal": false,
      "toolEnabled": false,
      "team": "off",
      "model": "off",
      "thinking": "off"
    }
  }
}
```

`enabled: false` запрещает вызовы всем проектам. `defaults` используется до первой сохранённой политики проекта; полная политика хранится в `server.db`. Таймаут ограничивается 100–30000 мс, размер запроса — не более 128000 байт. Настройка серверного endpoint недоступна агенту; HTTPS обязателен, HTTP допускается только для локального тестового сервера. Redirect отключён, ответ ограничен 256 КиБ.

По умолчанию проект допускает до 40 вызовов и $0.10 Jev на одну задачу, минимальные confidence и отрыв — 0.7 и 0.2. До отправки резервируются число обращений и консервативная сумма по размеру запроса. При потерянном ответе резерв остаётся, поскольку вызов мог быть оплачен. Автоматических повторов provider-запроса нет. При наличии usage учитывается фактический input, включая оплаченный ответ неверного формата. Токены также попадают в общую статистику/бюджет задачи; тариф Jev берётся из настройки сервиса, а не из нулевой цены локального каталога pi. История решений показывает стоимость с большей точностью, чем сводная статистика.

При неопределённости, таймауте, ошибке провайдера, отсутствии ключа или исчерпании разрешённого расхода автоматический выбор сохраняет предложение менеджера. При изменении фактов или конфигурации за время оценки запуск отклоняется: нужно повторить его с актуальными данными. Сеть не вызывается под блокировкой SQLite. Изменения уже работающей команды и смена модели участника пока используют существующие ручные операции и не вызывают автоматическую переоценку.

## Проверка

`cargo test -p genie --test it decisions::` проверяет интеграцию с локальным HTTP-имитатором: wire-протокол, CLI/MCP, авторизацию, область задачи, роли, расход, ошибки, неопределённость, режимы выбора, preview, override, устаревшие данные и конкурентный запуск. Ключ TypeSafe и оплачиваемые обращения для этих тестов не нужны.

Для оценки пользы нужны отдельные сопоставимые прогоны задач с Jev и без него: качество приёмки, возвраты ревью, время и стоимость принятой задачи. Интеграционные тесты проверяют корректность механизма, но не доказывают качество решений Jev. API/тарифы: [TypeSafe Models](https://docs.typesafe.ai/models), [Choice](https://docs.typesafe.ai/primitives/choice), [Confidence](https://docs.typesafe.ai/confidence).
