# Предложения к развитию genie

Разбор [[platform/roadmap]] на `main` (коммит 18cc275) со сверкой по коду и CHANGELOG. Владелец согласился с анализом 2026-10-03; рекомендации ниже — решения по умолчанию, пока не сказано иначе.

## Коротко

1. **Сначала — проект пилота.** Фаза 0 сделана больше чем наполовину (G-80…G-90); остаток держит выбор проекта: от него зависят окружение (G-108) и сам пилот.
2. **Менеджер проекта вырастает из нынешнего оркестратора**, а не заводится отдельной ролью. В фазе 1 ему добавляются память и чаты, в фазе 2 ведение команд уходит оркестраторам эпиков.
3. **Чат с менеджером — разговоры по темам с общей памятью**, а не одна вечная сессия: сейчас письмо другого человека перезапускает единственную сессию с его ключом (`sessions.rs`, `deliver`).
4. **Память — таблица в трекере проекта с источником**, а не раздел vault. Подбор нужного — FTS5 плюс Jev (ниже).
5. **Сводки из фазы 3 — уже в пилоте**: почти всё для них есть (cron, шаги `agent`, `task.create`, `notify`, MCP-шлюз).
6. **Минимальный срез окружения (mise) — в фазу 0**, если проект пилота не на Node или Rust.
7. **Еженедельная ретроспектива** — с пилота: роли, права и составы команд улучшаются по реальным задачам.

Порядок: проект пилота → остаток фазы 0 и окружение → пилот (со сводками и ретроспективой) → дизайн-заметка «память и кто кому пишет» → фаза 1 → разбивка `runtime.rs` → фаза 2 → остальное из фаз 3–4.

## Фаза 1: менеджер и память

**Таблица `memory`** в трекере проекта:

| Поле | Смысл |
|---|---|
| `kind` | договорённость, предпочтение, отложенное, уже пробовали, факт о проекте |
| `scope` | проект, эпик или человек (предпочтения человека — только в его разговорах) |
| `text` | одна мысль, до ~400 знаков |
| `source` | задача, комментарий или разговор, откуда взялось |
| `author`, `at`, `reviewAt` | кто записал, когда пересмотреть |
| `supersededBy` | запись, которая отменяет эту |

- Пишет — `genie memory add|forget`; журнал `memory.*` в той же транзакции.
- Забывает — по `reviewAt` менеджер спрашивает «ещё актуально?»; отменённое скрывается, а не удаляется; раз в неделю похожие записи сжимаются.
- Люди видят и правят — страница «Память» проекта.
- В vault запись уходит обычным предложением, когда доросла до знания.

### Подбор памяти через Jev

Перед каждым пробуждением менеджера сервер отбирает нужные записи и страницы и подаёт их в промпт.

1. **Кандидаты:** 30–50 записей памяти и страниц vault (название и описание) по FTS5, связям задачи и эпика, путям кода — расширение L1 из `crates/genie/src/context.rs`.
2. **Отбор:** [Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) (TypeSafe AI) отвечает по каждому кандидату «нужно ли для ответа на письмо» с вероятностью. Модель не пишет текст, а выбирает из заданных вариантов; контекст 32 тыс. токенов, вход $0,042 за миллион, выход бесплатный, есть прямой API и OpenRouter (по поисковой выдаче на 2026-10-03, перепроверить).
3. **Подача:** всё выше порога в пределах бюджета; закреплённые записи — всегда.

Решения: источник правды — таблица genie, Jev только выбирает; поиск за одним интерфейсом `recall(запрос, область)` — без ключа работает FTS5; у проекта есть «не отправлять во внешний API»; в журнал пишется, что подано менеджеру, а у него остаётся свой `genie memory search`. Тот же шаг пригодится для дедупликации находок (фаза 3) и сортировки входящей почты.

### Чат с менеджером

- Каждый разговор человека с менеджером — своя сессия pi с ключом этого человека; общая только память. Системная почта (доклады команд, события) — в служебную сессию менеджера.
- `plan.json` планировщика становится общим артефактом «предложение»; разбор идеи — режим чата менеджера.

**Готово, когда:** два человека независимо планируют работу в своих разговорах; через неделю менеджер в новом разговоре называет договорённость из старого со ссылкой на источник.

## Фаза 2: оркестраторы эпиков и планирование

- `AgentKey::Epic { project, epic }`: заводится с первой командой эпика, спит и просыпается как любая живая сессия, останавливается с закрытием эпика. Команды задач эпика пишут ему (адрес `orchestrator` разрешается сервером по задаче); людям он пишет через `needs_owner`, менеджеру — только о плане.
- Пульт `genie orchestrate --epic`.
- План: упорядоченная очередь эпиков и задач с решением «выпускать»; `ready-next` берёт из плана; бюджет эпика виден оркестратору заранее; окна работы; слот получает задача выше в плане (сейчас — порядок обхода).
- Риск: два эпика в одних файлах. Следит менеджер при выпуске или сервер по пересечению изменённых путей в открытых ветках.

**Готово, когда:** два эпика идут параллельно, у менеджера за день не больше N сообщений от команд, ни одна задача не стартовала без решения в плане.

## Фаза 3: рутины

| Рутина | Из чего | Не хватает |
|---|---|---|
| Утренняя сводка (личная и проектная) | cron → `agent` → `notify` | шаг `digest`: события и задачи за период без модели |
| Журнал пилота | то же → предложение в vault | — |
| Sentry, логи, алерты | webhook или cron + MCP через шлюз → `agent` → `task.create` | ключ находки: повтор дописывает задачу, а не создаёт новую |
| Уборка документации | cron → документатор по устаревшим страницам | выборка устаревших страниц как вход шага |

**Готово, когда:** команда пилота неделю получает сводку и не отключила её; одна ошибка Sentry — одна задача.

## Фаза 4

- **№ 6, ревьюер:** режим «предлагает» — `review.patch` к вердикту, исполнитель применяет `genie review apply`. «Коммитит» — только мелкие правки и без `approved` на свой коммит; решать по доле мелких возвратов в пилоте.
- **№ 9, провайдеры:** личные ключи провайдеров тем же механизмом, что ключ LiteLLM (`secrets.key`, выбор по инициатору). Подписки через `/login` — только для агентов самого владельца входа. В `usage` добавить инициатора и источник ключа; «ключ проекта» для рутин.
- **№ 7, документация:** L0/L1 уже есть; остаётся impact (какие страницы задевает дифф). Сначала замерить в пилоте, помогает ли L0.
- **№ 8, окружение:** кэш по хэшу lock-файлов, `doctor`, контейнерный исполнитель после пилота. Токены приватных реестров — только у песочницы подготовки.

## Еженедельная ретроспектива

Раз в неделю рутина разбирает работу агентов и заканчивается 3–5 обоснованными предложениями правок навыков, ролей, прав и состава команд. Следующая начинается с проверки принятых.

**Читает:** причины `changes_requested` и число кругов ревью; вопросы `needs_owner`, время и тексты ответов; сбои, таймауты и циклы; отказы прав (`git.denied`, отсечённые защитой и шлюзом MCP вызовы); расходы по ролям и моделям (`usage`); составы команд у задач, прошедших с первого раза, и у вернувшихся.

**Предложение:** что меняем (правка роли, навыка, права, шаблона, модели) · обоснование со ссылками и цифрами · ожидаемый эффект · как проверим через неделю · риск.

**Принятие:** «Принять» или «Отклонить» с причиной, как ревью предложений базы знаний. Принятое сервер применяет к конфигурации ролей и шаблонов с версией для отката; причина отказа — в память; не помогшее через неделю предлагается откатить.

**Ограничения:** агент ретроспективы только читает и не меняет свою роль; расширение прав — только предложением; правка промпта перед применением прогоняется на эталонных задачах (пробел 1).

**Этапы:** пилот — плейбук из готовых шагов (cron → `agent` с отчётом-артефактом → `notify`), правки руками; после пилота — структурированные предложения, применение кнопкой, версии и откат; в фазе 1 ретроспективу ведёт менеджер и пишет выводы в память.

## Чего не хватает до 1.0

| № | Пробел | Что сделать | Когда |
|---|---|---|---|
| 1 | Нет проверки качества агентов | эталонные задачи на учебном проекте, прогон «до и после»: дошло до «Готово», возвраты, стоимость | до пилота |
| 2 | Инъекции через внешний ввод (Sentry, логи, PR, почта) | агент с внешним вводом только читает и заводит задачи; проверка секретов при push — в фазу 0 | до фазы 3 |
| 3 | Обновления, когда команда уже живёт в genie | версионные миграции с проверкой на копии, тренировка «обновил — откатился» | до пилота |
| 4 | Шум уведомлений | настройки и тихие часы вместе со сводками | в пилоте |
| 5 | Переезд из Jira и Confluence | разовый импорт задач с эпиками и страниц в vault | фаза 1 |
| 6 | Человек не подхватывает работу агента (RQ7) | `genie take G-7`: ветка и контекст к человеку, возврат агентам | фаза 2 |
| 7 | Система не учится на результатах | ретроспектива (выше) | в пилоте |
